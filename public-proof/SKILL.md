# Public Proof

Convert built work into legible public evidence. The owner's recurring gap: strong outputs exist (daily games, agent systems, shipped apps) but stay invisible. Breadth only counts when it's legible. **Proof chain: project → demo → case study → post.**

## Voice Rules (non-negotiable)

The owner's voice, not AI-slop. Drafts have failed before because "the voice wasn't his."

- **Source from his real artifacts**: build-notes, iteration-log, commit messages, actual numbers (sessions, days, prototypes shipped). Quote specifics; never invent.
- **Honest build notes tone** — what worked, what broke, what he'd do differently. Failure detail is the credibility.
- **Banned**: "I'm thrilled/humbled/excited to announce", "game-changer", "🚀🔥 spam", rhetorical-question openers, "In today's fast-paced world", em-dash-heavy listicle sludge, fake vulnerability.
- **His angles** (use the one that fits, don't stack all): non-programmer shipping real systems with AI · game-designer thinking applied to AI systems (roles, rules, escalation) · building from Ludhiana, India · family/seva enablement.
- Short sentences. Concrete nouns. One idea per post.

## Deliverables (pick what was asked; default = all three)

1. **Case study** (300–600 words, markdown): Problem → What I built → How (the interesting decision, not the tutorial) → Proof (numbers, screenshot/GIF refs, repo link) → What broke / what's next.
2. **LinkedIn draft** (<200 words): hook line from the *most surprising concrete fact*, 3–5 short paragraphs, one CTA (repo/demo link). Write 2 variants with different hooks; label which he should post.
3. **Vault entry**: save the case study to `~/Documents/Satbir Life OS/30-public-proof/` as `YYYY-MM-DD-<slug>.md`. This is the durable archive Rehmat's radar watches.

## Evidence Gathering

Before writing, collect: what the project IS (README/CLAUDE.md), 2–3 concrete numbers (dates, counts, sizes), the one hard problem solved, and a demo path (playable link, screenshot, GIF). If no demo artifact exists, say so and list the 15-minute action that would create one — proof without a demo is half-proof.

## Guardrails

Never publish/post anything yourself — deliverables are drafts for him to post. Never pad thin work into fake significance; if the work isn't proof-worthy yet, say what would make it so.
